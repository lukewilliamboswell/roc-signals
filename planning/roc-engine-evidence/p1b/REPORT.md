# Phase 1b: reconcile API with storage (2026-11-04, nightly 2026-11-03-34bd006)

Verdict: representation D (one closure per site) keeps updates in place, passes
the heterogeneous-tree gate at ~10x, but code size per component (~18 KB vs ~4 KB)
is the new blocker for Wasm.

## Upstream
roc-lang/roc#12841: a list captured by two closures is copied on every update
under --opt=speed, depending on unrelated callers. Repro: h1/min4.roc vs min4b.roc
(1,002 copies vs 2 allocs from deleting an unrelated caller). dev always in place,
interpreter always copies, --specialize=no 6,004 allocs. Plain records of list
fields are in place in every mode. Hazard 4 not reproducible standalone (h1/h4.roc).

## Representations (rep/main.roc; one-row update at 1k/10k/100k, exact counts)
- A record of closures sharing a column: 1/45 here, 40*N bytes in 0a's module. Fragile (#12841).
- D one closure per site: 1/45 at every size; nested 2/101; query 0/0. Chosen.
- C static composition: 1/45; heterogeneous children need Both/tuple types.
- E universal Value union: 1/45; create ~2.3x bytes plus codec cost.
- (b) erased ops taking state as arg: not expressible (no existentials).
Rules: one capturing closure per site, never a record of closures, destructure,
exact allocation ratchets per operation.

## Engine on D (d/Engine.roc, ~500 lines) and the mixed-tree gate
Sites are single closures over (ctx, Msg, Tx); Val = {mask, read}; handlers are
ctx -> ctx; route table node id -> site path; propagation by layer mask, equality
pruned. App generated by gen.py: 2,000 mounted, 2,500 distinct components, mixed
state types, no `each`.

D native --opt=speed, n=10 medians:
| Mounted | Mount | Sparse | Swap |
|---|---|---|---|
| 200 | 0.256 ms | 3.7 us | 0.061 ms |
| 2,000 | 4.99 ms | 12.9 us | 1.22 ms |
Exact work at 2,000: mount 4,001 evals; sparse 2 evals + 1 SET_TEXT + 1 SET_ATTR;
swap 1,001 evals + 1 REMOVE. Allocs at 2,000: mount 16,383; sparse 6 allocs/8.6 KB;
swap 3,798. Sparse bytes grow slightly with N (3.3/4.4/8.6 KB at 50/250/2,000), unexplained.

Current engine, 200 mounted (ReleaseFast, --host-bench-app, n=7): mount 2.95 ms
(9,715 Roc + 16,251 host allocs), sparse 0.033 ms, swap 1.21 ms.
Gate (<=50%): mount 8.7%, sparse 11%, swap 5%. PASS at 200. 2,000 comparison pending
(locked.sh / locked2.sh were queued behind a hung Phase 1 benchmark).
Caveats: native only, no JS/DOM; command streams similar not identical.

## Costs
Code size (text): D 9.3/22.6/49.7 MB at 250/1,000/2,500 components; current
2.9/6.0 MB at 250/1,000 (incl ~1.9 MB host). ~18 KB/component vs ~4 KB.
Cause: generic engine monomorphized per context type. Open question: can the
context-generic functions be thin wrappers over context-free code?
Compile time: D 1 min / 3 min / 7m51s (8.3 GB); current 1.5 min / 58 min / killed at 90 min.

## API (api/DUi.roc, Canary.roc, TaskRow.roc, NestedEach.roc; roc test passes)
State handles are lenses (val, update, update_by) lifted inward with .lift() /
.lift_row(); every input crossing a state or row boundary needs an explicit lift.
Missing lift_row is a readable type error. No memoised shared derivation yet.
`each` is a stub: 0a's column store not yet wired into D.
