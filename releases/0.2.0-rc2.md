# 0.2.0-rc2

## Migration: 0.2.0-rc1 → 0.2.0-rc2

Use Roc `nightly-2026-09-04-c125b82`, as recorded in the example app headers
and release manifest. Update the platform URL, rebuild the application's Wasm,
and deploy the browser runtime from this release together. Do not mix a new Roc
platform module with an older native host archive.

`Http.Error` now includes `ResourceLimit(Str)` for capacity refusal. Add a case
when matching HTTP errors exhaustively. Explicit task cancellation publishes
the task's declared cancellation value, and late results from canceled requests
are ignored. `Signal.cancel(task)` exposes cancellation as a command.

Use the `Http` service helpers and `Signal.fake_task` for application task
construction. The low-level `Signal.task_source_with_eq` now takes a
`Signal.TaskConfig` record containing `name`, `reset_on_start`, `canceled`, and
`refused`, followed by the decoders and equality functions. Code using that
platform constructor must supply its cancellation and capacity-refusal values
explicitly. Task types are associated with `Signal` as `Signal.Task` and
`Signal.TaskStatus`.

`Ui.State.update_cmd` adds a pure transformation of the state's settled value
when the command executes. Its callback must be pure because preparation may
evaluate it again after refusal.

For repository consumers, `platform/` is now `platform-web/`, browser examples
are under `examples-web/`, and shared Roc modules live in `platform-shared/`.
Run `python3 scripts/prepare_platforms.py` to stage shared sources for local
builds. Published platform archives remain self-contained.

## Dependency and release provenance

The Linux musl libc and startup objects are built from pinned source in their
own CI workflow and released independently of the platform. Platform builds
verify the locked archive digest, signing workflow, source commit, and source
ref, including on cache hits. Changing the platform host no longer requires
rebuilding these external inputs. Compiled dependency binaries are no longer
checked into the repository.

Platform, browser runtime, starter, and site artifacts receive build attestations
after their candidate checks. Publication uses those tested bytes, and the
workflow verifies actual downloads before updating public URLs. New releases
are immutable. Historical releases are not retroactively attested by this work.

Source builds now need an authenticated GitHub CLI to verify dependency
attestations. Users of the complete published platform do not need Zig or a
repository checkout. Downloadable examples include the exact Roc compiler pin.

## Native GUI development

The repository now includes a GPUI host and six maintained GUI examples sharing
the reactive engine with the browser host. Linux CI builds the applications and
opens them under a virtual Wayland desktop with software Vulkan; Windows CI
builds the applications and runs their native semantic specs. These checks do
not require a physical GPU.

Windows ADVAPI32 import libraries have their own pinned, attested dependency
release. Rust dependency caching is separate from host compilation, and the
release profile avoids cross-crate LTO. Linux GUI system libraries, macOS SDK
stubs, and prebuilt GUI host admission still have provenance gaps documented in
`dependencies/README.md`. The web release artifacts do not constitute a complete
verified cross-platform GUI distribution.
