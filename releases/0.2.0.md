# 0.2.0

## Migration: 0.2.0-rc3 → 0.2.0

0.2.0 is the first final Roc Signals release. It publishes one web platform
package — browser applications plus the native semantic test host — and
`signals-examples.zip`. Use Roc `nightly-2026-10-23-18478ff`, as recorded in
every example header and in `signals-release.json`.

## Breaking: effects are actions; tasks are gone

Event handlers, change observers, mounts, and timers now return an `Action`.
An action is data the engine interprets: `Action.update` applies a batch of
state writes, and `Action.then` applies a batch and then runs effectful Roc
code whose result is the next action. Declared reads are snapshotted when the
event fires and again, freshly, before each effect. Import `pf.Action`; the
platform now also exposes `Event`.

The task transport has been removed: `Signal.Task`, `Signal.fake_task`,
`Signal.start_str`, `Signal.fold_task`, `Signal.noop`, and the task sources in
`Http` no longer exist. Keep a request's result in `Ui.state` and start it
from an action instead — `Action.on_change_initial` with `Action.sampled` for
a request driven by a signal, `Action.on_mount` for one-shot work, and
`Action.every` for polling. `Http.send!`, `Http.get!`, and `Http.get_text!`
are effectful calls made from inside `Action.then`, returning
`Try(_, Http.Error)`. Effects admitted before a scope is disposed still run;
their writes to disposed state are skipped. Rejecting an obsolete response is
application policy — `examples-web/package-explorer` keeps a generation
alongside each result for this.

`Ui.State` handlers are renamed from `on_*` to `update*`: `on_unit` →
`update`, `on_str` → `update_str`, `on_bool` → `update_bool`, `on_detail` →
`update_detail`, `on_key` → `update_key`, and each `on_*_with` →
`update_*_with` (`on_unit_with` → `update_with`). They return a
`Node.Handler`. `Ui.State` also gains `read` and `set`.

`Elem` is now a web platform module rather than a shared one, and the module
is the type: replace `import pf.Elem exposing [Elem]` with `import pf.Elem`;
annotations keep writing `Elem`.

The browser protocol is now version 17 (0.2.0-rc3 used 14). Serve the
JavaScript runtime from this release's `signals-examples.zip` (`browser/`)
with applications built against this platform package; the runtime checks the
module's protocol version at mount and refuses a mismatch.

## Breaking: the GUI platform has moved to roc-gui

The native desktop GUI platform — the `platform-gui` package, its GPUI host,
the `Files`, `Http`, and `Env` native services, and the `examples-gui`
applications — has been removed from this repository. It is now developed in
[lukewilliamboswell/roc-gui](https://github.com/lukewilliamboswell/roc-gui).
Releases from this repository publish only the web platform package; the
combined release no longer contains a GUI archive.

Applications that import the GUI package URL from an earlier Roc Signals
release (such as 0.2.0-rc3) keep building against that immutable archive, but
receive no further updates from here. Move them to a roc-gui release to
continue. Web applications are unaffected apart from the removal of
native-only vocabulary that the browser host already rejected, such as
keyboard-shortcut chords and window-close declarations.

The browser runtime now rejects creation over a live DOM node id. Replacement
must remove the old node or its ancestor before reusing the id, so behaviour
cleanup and listeners remain attached to the correct lifetime. Existing engine
command streams already follow this order; no application migration or wire
version change is required.

Transaction preparation preserves settled signal caches and retained ownership,
while action continuations still receive fresh post-commit reads. Empty keyed
list registrations are released with their declaring scopes. Transaction-index
reset and nested row-mirror updates now follow touched entries rather than
retained table capacity or the complete row mirror.

The native allocation-failure campaign now retries refused fixture registration
and effect-result preparation without rerunning the effect that produced the
result.

Unexpected command execution failures after a DOM event now contain the mount,
detach listeners and behaviours, and reject later dispatch. Recovery requires
a fresh mount; a partially applied command batch is never retried and
already-applied DOM changes are not rolled back.

Roc `nightly-2026-10-23-18478ff` miscompiles some conditional views under the
wasm32 dev backend ([roc-lang/roc#12560](https://github.com/roc-lang/roc/issues/12560)):
a `Ui.when` branch that was left is never re-selected. Build Wasm applications
with `--opt=size` until a pinned compiler contains the fix. Native builds and
`roc test` are unaffected.
